# Steam 游戏生涯拼图

`wall` 使用当前用户的关联；`wall_explicit` 和页面 `wall_preview` 必须明确提供账号。关联属于用户声明，不是 Steam 所有权验证。页面保持真实 `WEB_PUBLIC` 来源，不创建聊天身份或发送消息。

默认 `dense / standard / 2:3 / normal / cover`，最多纳入500项，包含软件及未知类型，排除零时长和未知时长。明确保存的 `poster_include_apps=false` 继续只看已确认游戏。`--mode legacy` 保留旧 WeightedCollage，最多200项。

`--source games` 是 XML 最多5项公开样本，`recent` 是主页最多3项最近展示样本。`full` 经 Core 注入部署者配置的可选 Steam Web API Key，请求真实库；模块不读取明文 Key。未配置、无效、私密或上游失败分别反馈，不用样本替代。`complete_library` 仅描述 API 来源覆盖；筛选与入图完整性另有 `all_eligible_included` 和 requested/eligible/included/omitted 计数。

支持 `--preset single|standard|long`、`--aspect 2:3|9:16|1:2`、`--quality normal|hd`、`--fit cover|contain`、`--limit 1..1000`、`--all-apps`、`--games-only`、`--refresh`。2:3为原版竖海报；窄版 cover 等比裁剪，contain 保留全图并填背景。

锚点间线性插值面积，再对平方根按 half-up 量化为整数倍率。每张占 `k×k` 格；大小不依赖库内最大时长。正常基元为54×81/96/108，20列内容宽1080；高清整体放大4/3为72×108/128/144，内容宽1440。Core 大块优先、稳定补空；物理阅读顺序可跨逻辑排名区间，同分逻辑列表按数值 AppID。过长标题明确显示省略号，AppID保持完整。

先筛选并检查有限页面预算，再以100项一批准备元数据/所选图片；单次素材能力仍最多200项，HTTP并发4。一次最多核查1000个正时长候选类型，未核查范围明确计数，不声称类型筛选覆盖完整。普通/高清、预设及比例共享同一官方竖封面原始变体。原图与纯源衍生共用 Core PUBLIC 二进制持久缓存，最多2048项/256MiB；PUBLIC 衍生按源 hash、尺寸、fit 与版本跨用户复用，不含账号、选集或文案。个人二进制分区保留512项/64MiB；个人快照、选集和成图按用户隔离，页面不缓存个人选集或成图。完整库快照保留300秒，并按可信凭据修订隔离；清除或轮换 Key 不复用旧快照。

成图最多8页，每页4MiB PNG、总16MiB；渲染输入素材总32MiB、每页8MiB，实际像素和内存预算由 Core 测量页头/页脚后一并执行。1000项是压力边界，不承诺任意1000张最大倍率都能发送；超限会提示降低数量、清晰度或选择较小倍率预设。

Core 可信索引绑定源内容 hash、资源修订及文件版本，Windows 额外使用 ChangeTime；文件变化或证据未知时完整复核。首次复核保留的原字节有32MiB上限；冷处理期间短期保留来源读取租约，避免衍生入库驱逐本轮尚需使用的原图，不延长有效期。成图命中仍完整读取并校验 PNG，不逐张全读/解码封面。共享衍生命名空间仅允许 Core 按经过验证的公共原图生成，不接受模块任意 PNG 或缓存 payload；私人/授权源不进入公共缓存，授权调用不持久化衍生或成图。文件系统能伪造全部变更元数据的攻击、未引起文件版本变化的静默位腐化不属于轻量版本证明的保证。
