# Dota 2 自动赛后通知

本模块通过 OpenDota 的公开数据查询玩家资料、近期比赛、统计和战报，并为当前会话提供赛后订阅。数据未公开、尚未入库或字段缺失时，会保留等待或未知状态；不会主动提交比赛解析，也不会把缺失数据当成零。

## 命令与身份

| 命令 | 行为 |
| --- | --- |
| `/ygl dota2 watch [ID32或SteamID64]` | 为自己在当前会话关注该玩家；省略账号时读取已绑定的 Steam 身份 |
| `/ygl dota2 watchlist` | 查看自己在当前会话的订阅、基线、待补数据和跳过积压数量 |
| `/ygl dota2 unwatch <玩家ID或订阅编号>` | 取消自己在当前会话的订阅 |
| `/ygl dota2 status` | 查看模块开关、轮询间隔及共享 OpenDota 请求预算 |
| `/ygl dota2 analyze <比赛ID> [--account <ID32/SteamID64/本局唯一昵称>] [--refresh]` | 指定玩家的详细结算/已有解析分析；省略账号或使用“我”仅通过可信本人绑定解析；命令由 Core 请求 Host 模型 |

ID32 接受 `1..4294967295` 的整数，也接受可规范化为个人账号的 SteamID64。创建时固定解析后的账号，之后更换 Steam 绑定不会自动改订阅目标。重复关注同一账号会返回现有有效订阅；取消后重新关注会建立新的订阅和基线。

订阅管理只接受真实命令提供的用户和完整会话路由，不能通过模型调用或网页参数指定任意用户、群组或私聊目标。

## 采集、恢复与合并

同一公开玩家在多个会话中的订阅共享一次采集，各会话保留独立订阅状态和发送记录。首次完整成功采样只建立基线，不推送历史比赛；失败或部分采样不会建立基线。

基线之后发现的新比赛先进入持久待处理队列，等待可用的公开结算数据。恢复窗口为 **24 小时**：每次完整恢复采样最多保留时间最新的 **3 场**候选，包含已有待处理比赛；较旧积压跳过并计入 `watchlist` 的省略数量。每场比赛仍是独立事件。该上限不表示对未来任意延迟才发现的数据提供全局“恰好三场”保证。

共享采集的上一份已提交观察与每订阅首次基线、评估游标分开保存。新订阅、代表订阅变化、取消或重新创建，不会清空已有采集的待补详情。

同一完整会话路由内、同一比赛合成一条战报。首次取得的有界公开十人结算可用于逐一匹配当前目标的有效订阅，因此另一玩家的近期列表晚到超过 **30 秒**仍可进入第一份战报；不靠延长聚合窗口等待。投影必须满足该订阅自己的首次基线、已处理状态和当前 generation。不同群组、私聊、适配器或投递路由分别匹配、分别投递；匿名或身份冲突不会按英雄或昵称猜账号。每个目标最多重评100个当前订阅，超过资源预算明确拒绝该轮评估，不静默取前100或推进游标。

现有约30秒窗口仍用于封包调度。发送任务领取后成员集合封存；迟到重复贡献保留抑制原因和原始记录，不追加第二条或假记为已发送。稳定业务去重不随展示模板、语言、事件格式版本或 composer 改名而重发已投递比赛，旧 SENT/UNKNOWN 历史仍有效。模型生成和发送前重新检查成员；取消/重建后重新组成有效焦点集合。无新比赛时不发通知，也不主动 @ 玩家。

## 指定玩家详细分析

命令和 `steam_dlc_dota2_analyze` Tool 使用相同的 `match_analysis` v1 归一化事实。Tool和页面必须明确给出比赛及账号/本局唯一昵称，不读取默认绑定、不递归请求模型；重名返回候选账号，匿名、未参赛或无法核验阵营明确说明。命令通过Core托管的既有Host provider生成AI分析，使用空历史、无工具、不保存会话，不新增模型Key。模型未配置、超时、额度不足或失败时保留确定性报告并标注“AI分析未生成”；自动赛后通知不会调用详细分析。

仅 GET 来源已有数据，不申请录像解析。基础结算与补刀、经济/经验、伤害、治疗、最终装备保留缺失/零值区别；来源提供时读取发育时间线、购买记录、对线位置、团战、目标、天辉团队经济/经验差及基准。时刻为相对比赛开始的秒；来源提供 `times` 时使用其时刻，否则 gold_t/xp_t 使用分钟索引。胜负按焦点阵营解释；没有依据时不判断走位、眼位、沟通或死亡原因，不宣称看过第一视角录像。

响应最多4,000,000字节；每位玩家的完整有界投影最多181个时间点、80条购买记录、8项基准，全场最多20段团战和80条目标事件，截取与缺失均明确记录。给模型的压缩摘要另含采样说明，并由真实Core Gateway和公开事实扫描器校验512节点预算。完整公开投影按比赛缓存；`--refresh`只重新GET已有解析。AI结果缓存另外区分焦点、事实摘要、语言/模板、Host模型配置、主体/完整路由及权限，不跨玩家或群复用私人上下文。

## 配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `subscription_enabled` | `true` | 暂停或恢复订阅采集及待发送通知；保留订阅，仍可查看和取消 |
| `poll_interval_seconds` | `300` | 允许 `60 / 300 / 900 / 3600 / 21600 / 43200 / 86400` 秒 |
| `opendota_rph` | `100` | 同一 OpenDota 来源共享的每小时请求预算，必须为正整数 |
| `commentary_enabled` | `false` | 在确定性战报中加入可选的模型短评 |
| `credential_opendota_key` | 未配置 | 通过受信任设置管理的可选 OpenDota Key |

空值恢复相应默认值。轮询间隔在后续到期采集时读取当前配置，不立即提前已有任务的到期时间。暂停期间不接受新增关注。

OpenDota Key 可选；匿名公开查询受来源可用性限制。配置了无效 Key 时报告来源错误，不悄悄退回匿名请求；配置 Key 也不会自动提高本地预算。不要在聊天命令中提交密钥。

预算按滚动 60 分钟内实际外部请求次数计算，手动查询、模型查询和订阅共享；缓存命中不计数，重试计数，分钟限制同时生效。预算和来源冷却持久保存，重启不重置。遇到预算耗尽或 `429 Retry-After` 时调度器等待恢复时间，不以失败采样覆盖基线。`status` 无法取得预算证据时显示未知，而非完整剩余额度。

## 可选短评与发送状态

短评只使用本次战报的公开结算事实，通过 Host 当前配置的模型做一次无状态调用：独立临时 session、空历史、不使用工具、不保存会话。默认最多等待 8 秒、采用最多 400 字输出；异常、超时、空响应或超长响应均回退到事实战报。每个已持久事件和模板仅尝试一次，重启不会重复消耗短评请求。短评不会把 KDA 等结算指标解释成未提供的走位、团战过程或因果结论。

发送前会再次核对订阅是否有效、路由、权限和开关；取消的成员不继续参与战报。Host 已开始发送但结果无法确认时，记录为 **UNKNOWN**，不盲目重发。进程重启会把遗留的发送中任务转为 UNKNOWN；尚未开始发送的领取任务可恢复待处理。UNKNOWN 表示无法确认是否送达，需要核对投递记录，不能作为成功或失败，也不构成端到端恰好一次承诺。
