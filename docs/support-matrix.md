# 支持与验证矩阵

本表区分代码/隔离证据与真实环境验收。冻结依赖为 Core `0.1.11`、canonical SDK `0.1.0a22`、module ABI `2.0`、bridge `1`、schema `210`。DLC `0.2.0-beta.1` 的 AstrBot 元数据下限是 `>=4.29.1`，它不是对所有未来 Host 版本的兼容保证。发布候选的完整环境和逐项结果应以该候选的公开 CI 与发布摘要为准；历史 `alpha.7` CI 不代表 beta 候选或现场通过。

| 类别 | 能力/环境 | 证据边界 |
| --- | --- | --- |
| 历史 CI | DLC `alpha.7` 自动化 | 仅适用于对应历史源码和工作流；不证明 `beta.1`、真实平台或 Host。 |
| 已有现场来源检查 | 原 Host 上保存的 Steam Key 完成一次真实只读完整库刷新；已有 Perfect 授权完成资料查询 | 这是本轮开始前对既有凭据/Host 的检查，不等于 beta 包安装后的完整回归或所有玩家可用性。秘密、账号和响应数据不公开。 |
| 隔离/合成 | 单元测试、去标识 fixture、合成双插件 harness、页面视口模拟 | 仅证明相应离线/隔离路径。它们不证明真实新比赛、IM、二维码、真实手机或线上 API。候选测试结果须看对应 CI。 |
| 未验 | 5E 真实查询及头像 | 未提供 5E Token/domain；保持实验性/未验。不得推测图床或把缺少凭据写成空数据成功。 |
| 未验 | Dota 真实 IM 投递和自然新比赛 | 没有受信目标、允许发送条数、时间窗和消息授权，本轮测试出站数为 0。管理页或合成事件不替代真实会话身份。 |
| 未验 | 非空 CS2/Deadlock 样本、真实手机、OS 重启、生产磁盘恢复 | 外部条件未提供或未执行；390px 视口模拟不代表真实手机，备份校验不代表生产磁盘恢复。 |
| 来源限制 | Steam 私密库、OpenDota 收录范围、完美/官匹/5E摘要、Deadlock 社区数据 | 受上游可见性、收录和凭据限制；官匹是完美收录口径，官匹/5E近期摘要不等于完整历史或完整单场。可选 OpenDota Key 不扩大 RPH。 |
| 部署条件 | Core 动态页面资源 | 使用 localhost/回环或可信 HTTPS。远程普通 HTTP 可能在父壳 hash 校验前置能力处失败；不关闭校验，也不承诺此部署方式。 |
| 冻结 Core 限制 | `CORE-K01` | 队列整批候选无法入场后，后续 queued 作业可能没有新唤醒；queued 仅查询或取消，不提示 retry。 |
| 冻结 Core 限制 | `CORE-K02` | 同群同模块/类型/来源累计 101 条 active PUBLIC 订阅可能超过投影 100 上限，影响共享 observation 的其他目标。 |

新安装使用 Release 中的 DLC ZIP，安装 Core 后安装 DLC，在 Core 可信管理页批准当前具体扩展安装计划，再正常重启 Host。GitHub 自动生成的 Source code.zip 是源码归档，不是插件安装包。已有兼容实例只更新 DLC；普通内容/页面摘要变化沿用 Core 和原安装许可。新增敏感权限需批准新的具体计划。

## 当前候选状态

此文档本身不把待执行或待复核工作标成通过。请以最终 beta Release 所附的公开摘要及对应提交 CI 查看候选的精确 Host、Python、操作系统和逐项结果；未列出可访问证据的项目仍按未验处理。
